# 麦麦图鉴 · 1024

> 把麦当劳菜单做成一本可以收集、可以玩的图鉴。
> 数据全部来自麦当劳中国官方 MCP Server，0 依赖，clone 下来双击就能跑。

你在麦当劳吃过多少种东西？大概率答不上来。

这个项目把它变成一件看得见的事：拉取你所在门店的**当期在售菜单**，和你的**历史消费订单**做比对，生成一本属于你自己的图鉴 —— 附带一个用 2 的幂做分值的合成小游戏，致敬 1024。

---

## 三分钟跑起来

```bash
# 1. 装依赖（零第三方依赖，只要 Node 18+）
git clone <你的仓库地址>
cd mcd-dex

# 2. 申请 MCP Token：https://open.mcd.cn/mcp （手机号登录，5 步搞定）
cp .env.example .env
#    把 .env 里的 MCD_MCP_TOKEN 换成你的 Token

# 3. 采集数据
export MCD_MCP_TOKEN=<你的 Token>
node src/collector.mjs

# 4. 打开页面
#    直接双击 web/index.html 即可，不需要起服务器
```

**不想申请 Token 也能玩。** 仓库自带一份脱敏示例数据 `data/catalog.js`（武汉某门店的 133 项真实菜单），双击 `web/index.html` 就能看图鉴、玩游戏。只有"已品尝"那条路径需要你自己的账号数据。

用 WorkBuddy / Cursor / Cherry Studio 等 MCP Client 的同学，也可以直接把 `mcp-config.example.json` 的内容填进客户端的配置里。

## 两个设计决定，是这个项目的全部

### 一、双轨图鉴：虚拟解锁不能污染真实痕迹

图鉴有两套独立统计，而不是一套：

| | **已品尝** | **已收录** |
| --- | --- | --- |
| 来源 | 只能是真实订单 | 真实订单 **或** 游戏合成 |
| 覆盖范围 | 全部品类，含限定与周边 | **仅限常驻餐品** |
| 视觉 | 金边 + 全息标记 | 灰边，标注"已收录" |
| 汇总 | **品鉴度** | **收集度** |
| 性质 | 不可刷 | 人人可得 |

对应的 UI 是这样的：

```
收集度 78%  ████████████████░░░░   含游戏，人人能刷满一部分
品鉴度 23%  ████░░░░░░░░░░░░░░░░   真实消费口径，不可刷
```

**为什么非要分开？**

因为稀缺性的本质是"对比"，不是"绝对难度"。如果打几局游戏就能点亮全部图鉴，那每个人的图鉴都是 100%，收藏就退化成一条进度条 —— 和任何一款肝度游戏没有区别，麦当劳这个场景反而变成多余的外壳。

所以限定品、季节新品、联名周边在游戏里**永远刷不出来**。你可以爽快地收下常驻部分，但永远凑不齐整套，剩下的只能靠真实的餐桌去补。这一刀下去，稀缺性才立得住，同时"还剩多少要靠吃才能拿到"也成了一个长期钩子。

顺带地，这个边界也让项目的口径变得干净：它是**记录生活痕迹**，而不是鼓励多吃。

### 二、1024 不是标题装饰，是数值系统

`1024 = 2^10`，是这个游戏的计分规则本身：

- 5×5 棋盘滑动合并，方块是**你那家门店真实在售的餐品**
- 进化链按真实售价升序排列，合成体验就是"越来越贵"
- 第 k 级的分值就是 `2^k`，合到第 10 级 = **1024 通关**
- 每合成出一个新等级，图鉴里对应的餐品自动点亮（记入"已收录"）
- 段位用职级命名：麦门见习 → 实习工程师 → P5 → P7 → P9 → 首席汉堡官

难度是量出来的，不是拍脑袋定的。仓库里的 `src/test-game.mjs` 会跑 120 局蒙特卡洛验证：

| 策略 | 通关率 |
| --- | --- |
| 随机乱滑 | ~2% |
| 启发式（靠角 + 保持单调） | ~21% |

真人掌握方法后会明显好于这个 depth-1 机器人，实际体感大致在三四成。**有挑战，但不至于绝望** —— 这点很关键，合不出 1024 的玩家是不会产生分享欲的。

## 项目结构

```
mcd-dex/
├── src/
│   ├── mcp-client.mjs   极简 MCP Streamable HTTP 客户端（握手 + 工具调用 + SSE 解析）
│   ├── collector.mjs    三源数据采集与合并，产出图鉴底表
│   ├── probe.mjs        连通性自检，配 Token 后第一条建议跑它
│   └── test-game.mjs    游戏逻辑与难度曲线验证
├── web/
│   ├── index.html       图鉴 + 游戏，单页
│   ├── style.css
│   ├── app.js           双轨状态管理、图鉴渲染、战绩卡导出
│   └── game.js          1024 合成游戏核心
├── data/
│   ├── catalog.js       脱敏示例数据（可开源，双击即玩）
│   └── catalog.json     可读版本，含个人信息，默认不入库
├── mcp-config.example.json
├── MCP_INTEGRATION.md   MCP 调用链路与数据处理细节
└── CONTEST_DECLARATION.md
```

## 数据口径说明

以示例门店（武汉）为例，一次采集得到：

| 稀有度 | 数量 | 判定依据 |
| --- | --- | --- |
| 品牌周边 | 2 | 商品名命中周边/棒球帽/毛绒等 |
| 限定 | 25 | 含「周末专享」「麦金卡」标签，或 30 天内上架 |
| 常驻 | 106 | 其余，**其中一部分进入游戏进化链** |

游戏进化链还会剔除套餐（按 tags 与商品名判定）和调味蘸酱 —— 配料不是一道餐品，放进去会让"合成"这件事失去意义。

## 关于隐私

- Token 只从环境变量读取，任何情况下都不会写进产出文件
- 采集结果里的手机号、门牌地址均不落盘；`data/catalog.json` 默认被 gitignore
- 游戏解锁记录存在浏览器 localStorage，不同步、不上传
- 项目不调用任何下单类接口
